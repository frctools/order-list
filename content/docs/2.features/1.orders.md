# Managing Orders

Orders are the core of Innovators Parts. Before anything else, it helps to know
how they are shaped, because it is not one row per part.

## Parts and orders

An **order** is a purchase from one vendor. The **parts** are the line items
inside it.

You never create an order directly. You add a part, say where it comes from, and
Innovators Parts puts it into that vendor's open order — creating one if there
isn't an open order for that vendor yet. Add three REV parts and two AndyMark
parts and you end up with two orders: one per vendor, matching the two checkouts
you will actually do.

::note
Status belongs to the order, not to the part. The whole order moves from
**To order** to **Ordered** to **Arrived** together, because that is how a real
purchase behaves — the box arrives, not individual parts.
::

## Order status

| Status       | Meaning                                                     |
| ------------ | ----------------------------------------------------------- |
| **To order** | Still being assembled. Parts can be added, moved and split. |
| **Ordered**  | Bought from the vendor and on its way.                      |
| **Arrived**  | Delivered.                                                  |

Marking an order **Ordered** or **Arrived** records the timestamp automatically.

## Adding a part

1. Click **Add part**
2. Fill in the details:
   - **Part name** (required)
   - **Vendor** — decides which order it joins
   - **Quantity**
   - **Unit price (USD)**
   - **External link** — the product page
   - **Notes**, **Variant**, **Tags**
3. Click to save

::tip
Paste the product URL first. For many vendors — REV, AndyMark, DigiKey, Playing
With Fusion, Online Metals, McMaster-Carr and other Shopify storefronts —
Innovators Parts reads the page and fills in the name, SKU and price for you.
::

### Prices below a cent

Unit prices accept more than two decimal places, because distributors genuinely
quote them: DigiKey's quantity breaks go to five. A price shows as plain money
when it lands on whole cents (`$2.40`) and spells out the extra digits only when
it really carries them (`$0.231`). Line totals are summed at full precision and
rounded once, so a thousand resistors do not drift by a few cents.

## The two views

Switch between them with the layout control above the board.

**Board** — three columns, one per status. Three things can be dragged:

- an **order onto a column**, to change its status
- a **part onto another order card**, to move it there (same vendor, both still
  **To order**)
- a **part onto the To order column**, to split it into an order of its own

**Table** — every part as a row, with filters for date range, vendor, status and
tag, and an **Export CSV** button that exports exactly what the filters are
showing.

## Splitting and combining

Plans change: something is needed sooner, or a part should ship separately.

- **Split into its own order** takes a part out into a new order for the same
  vendor.
- Dropping a part onto another order card **combines** it into that order.

Both only work between orders that are still **To order**, and only within the
same vendor — you cannot merge a REV order into an AndyMark one. If a move
empties an order, that empty order is deleted.

## Ordering from the vendor

Open an order and use **Order from vendor** to hand the whole thing to the
vendor's own site. Where the vendor supports it, this builds a cart in one
click. Shopify stores, Amazon and DigiKey work this way.

Some vendors only accept one part at a time. There you get a list of links
instead, ticked off as you follow them. Keep them in the same tab and the cart
builds up as you go.

Parts that could not be matched to something the vendor recognises are listed as
excluded rather than quietly dropped, so you know what to add by hand.

## Shipping, payment and totals

**Shipping & payment details** on an order records what the purchase actually
cost and how it was paid:

- **Tracking carrier** and **number**
- **Shipping** and **Tax**
- **Payments** — split across as many lines as you need, each a credit card,
  voucher, coupon or other

The split matters for FRC: an order part-paid by a Kit of Parts voucher and
part by a team card is one order with two payment lines, not two orders.

Totals are calculated, never typed:

| Total           | What it is                    |
| --------------- | ----------------------------- |
| **Order total** | Every line in the order       |
| **Shipping**, **Tax** | As entered              |
| **Grand total** | Items + shipping + tax        |
| **Paid**        | The payment lines added up    |

If **Paid** does not match the grand total, something is missing — an unrecorded
voucher, or a shipping charge nobody entered.

## Receipts

Orders take PDF and image attachments, which is what makes the record hold up
for a nonprofit audit. See [Receipts](/docs/features/receipts).

## Deleting

Removing the last part in an order deletes the order too, since an order with
nothing in it is not a purchase.

::warning
Deleting is permanent. Neither parts nor orders can be recovered.
::

## Part fields

::field-group
::field{name="Part name" type="string" required}
What the part is.
::

::field{name="Vendor" type="string"}
Who it is bought from. Decides which order the part joins.
::

::field{name="Quantity" type="number" required}
How many. Defaults to 1.
::

::field{name="Unit price (USD)" type="number"}
Price per unit. Accepts sub-cent values.
::

::field{name="Variant" type="string"}
Size, colour or length, where the vendor sells several.
::

::field{name="External link" type="string"}
The product page. Used for automatic lookups and vendor cart links.
::

::field{name="Notes" type="string"}
Anything else worth recording.
::

::field{name="Tags" type="string[]"}
Labels for filtering. Tags attach to parts, not to orders.
::
::
